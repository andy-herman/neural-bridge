# The Sept-Oct 2026 South Korean financial-sector intrusions and CrowdStrike's ARTEX report

Research date: 2026-10-09. Method note for the writer: the sandbox's egress proxy refused every direct page fetch (news sites, fsc.go.kr, crowdstrike.com, namu.wiki, GitHub API for third-party repos). All findings below come from search-engine result summaries of the cited pages, not from reading the pages in full. Numbers and quotes were cross-checked across multiple outlets where possible; anything resting on a single secondary outlet is flagged. The primary CrowdStrike post is https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/ ("Unknown Threat Actor Uses AI-Driven ARTEX to Target South Korean Finance", published 7 Oct 2026 US time, reported as 8 Oct KST). Korean-language titles are given with an English gloss.

## Which institutions were affected, and what was the customer-facing impact?

### Takeaway
Seven Korean financial firms confirmed data leaks between 28 Sept and 4 Oct 2026 (Shinhan, KB Kookmin, Hana, BNK Busan, Yegaram Savings Bank, Welcome Savings Bank, Hyundai Capital), with Woori and NH NongHyup reporting blocked attempts and no leak; the regulator's running total is "more than 68,000" people. This was data theft from peripheral, internet-facing loan-agent and employee systems, not an outage, ransomware or fraud: no core banking systems, passwords, OTP codes or funds were reported taken.

### Inferences
- Summing the per-firm figures (25,727 + 119 + 89 + 11 + ~40,000 + up to 2,200 + 146) gives roughly 68,300, which matches the FSC's "more than 68,000"; the lower 65,000-66,000 figures predate the Welcome/Hyundai Capital counts or exclude corporate records.
- Reuters' "nine banks" most plausibly = the seven leak victims plus Woori and NongHyup (attacked, no leak).
- The Shinhan timeline shows containment was partial for ~15 hours after detection, which is the detail most likely to drive Korean sanctions (reporting delay plus continued exfiltration post-detection).

### Gaps
- No outlet reports downtime for ordinary customers; the only service interruptions were the banks suspending the affected loan-agent/employee portals. Duration of those suspensions was not found.
- No report of secondary fraud losses yet; regulators only warn of phishing/social-engineering risk.
- Yegaram's 40,000 remains provisional; no final figure found.

## What does the CrowdStrike report claim about the attacker's AI workflow and evidence, and what is ARTEX?

### Takeaway
CrowdStrike (7 Oct 2026) says an unattributed, likely Chinese-speaking, financially motivated operator (moderate confidence) ran the Chinese open-source agentic pentest tool ARTEX on DeepSeek v4.1-flash (reached via the xcai[.]pro reseller) from server 38.244.50.120, while using Claude Code (with GLM-5.3 and Grok 4.6 in other sessions) from a Hong Kong server as a planning/research layer; the evidence is open directories exposing Claude Code session histories, Claude memory files, ARTEX configs and a résumé prompt with personal details. ARTEX is a Go/Next.js AGPL tool by the GitHub developer Autumn-27, released around July 2026, which the developer took private and stopped maintaining after the incident.

ARTEX itself
- ARTEX is an open-source LLM-based autonomous penetration-testing system distributed via GitHub, aimed at Chinese-speaking users; a planner agent splits a target into tasks and worker agents run them with real tools (shell commands, HTTP requests, port scans); it automates reconnaissance, vulnerability discovery, attack-path planning, security-tool execution and verification — [Seoul Economic Daily, "Traces of Chinese AI Hacking Tool Found on Server Tied to Shinhan Bank Breach"](https://en.sedaily.com/technology/2026/10/02/traces-of-chinese-ai-hacking-tool-found-on-server-tied-to); [Korea Times explainer](https://www.koreatimes.co.kr/business/banking-finance/20261007/explainer-how-ai-emerged-as-new-threat-in-koreas-bank-hacking-crisis)
- Main repository github.com/Autumn-27/ARTEX; developer is a Chinese security engineer publishing as "Autumn"; Go backend plus Next.js frontend, AGPL-3.0 — [Zendot, "ARTEX: A Self-Hosted Autonomous Penetration Testing System Written in Go"](https://zendot.org/en/posts/autumn-27-artex); first posted to GitHub in July (2026) — [Insurance Journal (Reuters)](https://www.insurancejournal.com/news/international/2026/10/08/888416.htm)

- The evidence chain is operational-security failure (world-readable directories), not telemetry from any model provider; CrowdStrike's "single actor" is inferred from one set of session histories, one Telegram handle and one résumé, which is why confidence is only moderate.

## What was the initial access vector and which weaknesses were exploited?

### Takeaway
Every confirmed breach went through an internet-facing auxiliary system (loan-agent portals, employee mobile work-support tools, sales-support databases) protected by simplified authentication rather than the certificate-based auth used for customer banking; at Shinhan the attacker got past identity verification on the "M Shinhan" loan-agent mobile site and enumerated customer records by cycling identifiers, with Korean outlets split between calling it "credential stuffing" (Yonhap) and "enumeration" (Dong-A Ilbo). No CVE has been named.

### Cited Findings
- Shinhan's target was the inquiry service on "M Shinhan", a mobile website for loan agents, accessible after a simplified authentication process unlike certificate-based general banking; the attacker cycled through randomised customer identification numbers and other query values until records came back, using IPs from Korea, the US and Japan — [The Herald Business, "Security flaw in loan agent portal behind Shinhan Bank data breach"](https://mbiz.heraldcorp.com/article/10891096); [American Banker](https://www.americanbanker.com/news/ai-linked-hacks-hit-korean-banks-through-loan-agent-sites)
- Shinhan's own account is that the intruder exploited the portal's "communication protocol structure"; Yonhap reported credential stuffing while Dong-A Ilbo described enumeration; it remains unclear how the phone-verification step was bypassed — [WindowsForum, "South Korean Bank Breaches Hit 25,000: Credential Stuffing and AI Tool Claims Examined"](https://windowsforum.com/news/south-korean-bank-breaches-hit-25-000-credential-stuffing-and-ai-tool-claims-examined.447262/); [Bloomberg](https://www.bloomberg.com/news/articles/2026-10-02/ai-tools-suspected-in-korea-s-shinhan-bank-hack-yonhap-says)
- Yonhap: attackers probably used AI agents to probe for vulnerabilities and gain unauthorised access to a service used by loan recruiters — [Bloomberg](https://www.bloomberg.com/news/articles/2026-10-02/ai-tools-suspected-in-korea-s-shinhan-bank-hack-yonhap-says); [The Star (Reuters)](https://www.thestar.com.my/business/business-news/2026/10/05/ai-tools-flagged-in-cyberattack-on-s-koreas-shinhan-bank)
- Entry points elsewhere: KB Kookmin's employee mobile work-support system; Hana's ODS sales-support DB; Busan's internal mobile sales-support system; Hyundai Capital's mortgage-loan-broker query page — [Korea Herald](https://www.koreaherald.com/article/10892290); [Seoul Economic Daily](https://en.sedaily.com/finance/2026/10/03/hyundai-capital-hacked-as-breaches-spread-to-non-bank)
- The Financial Security Institute (FSI, 금융보안원) found the IPs attacking Shinhan, KB Kookmin and Hana were nearly identical and bore traces of a Chinese-language AI hacking tool — [Hankook Ilbo, 인터넷망 노린 금융권 해킹, 예견됐지만 못 막았다… 대통령 "철저한 조사" (Internet-facing finance hacks were foreseen but not stopped; President orders thorough investigation)](https://www.hankookilbo.com/news/article/A2026100416390000753); same-IP finding also in [SBS Biz, 금융사 해킹, 동일 공격자 소행 가능성…동일 IP 여러 곳서 발견 (Finance hacks possibly same attacker; same IP found at multiple firms)](https://biz.sbs.co.kr/article/20000338258)

- The attacker rotated IPs; the FSS identified 19 attack IPs in 12 countries (US 5; Japan, Sweden, Germany 2 each; 1 domestic; also Hong Kong, Singapore, Vietnam, Thailand), later 28 unique (33 including duplicates) — [Korea Times, "19 IP addresses..."](https://www.koreatimes.co.kr/southkorea/law-crime/20261006/19-ip-addresses-behind-recent-hacking-attacks-against-korean-financial-institutions-watchdog); [Korea Times, "28 IP addresses..."](https://www.koreatimes.co.kr/southkorea/law-crime/20261006/28-ip-addresses-behind-recent-hacking-attacks-against-korean-financial-institutions-watchdog); [Digital Today, "...police open investigation after 28 attack IPs identified"](https://www.digitaltoday.co.kr/en/view/111318/financial-sector-hacking-spreads-police-open-investigation-after-28-attack-ips-identified); [Financial News, 금감원, 금융권 무더기 해킹 'IP 19개·12개국' 특정 (FSS identifies 19 IPs in 12 countries)](https://www.fnnews.com/news/202610061126488393)
- The AI made only a small number of login attempts per burst, so the traffic was mistaken for normal activity — [Hankyung](https://www.hankyung.com/article/2026100427061)
- Regulators cautioned that IP geography does not reveal where attackers are based — [Runtime Wire](https://runtimewire.com/article/south-korea-bank-breaches-artex-ai-probe)
- Entry points were "internet-facing internal tools with weak or bypassable authentication" — [Security Point Break](https://securitypointbreak.com/2026/10/07/beyond-shinhan-south-koreas-bank-hacks-hit-66000-with-an-ai-clue/); the Korean editorial stresses that loan-recruiter query systems and employee work-support systems, not retail internet/mobile banking, were exposed — [Nate editorial](https://m.news.nate.com/view/20261002n36684)
- Current Electronic Financial Supervisory Regulations require vulnerability checks once a year for general information systems and twice a year for public websites; the loan-agent and employee systems fell outside routine checks — [Money Today, AI 몰랐던 10년 전 규제 그대로…금융사 뚫리자 취약점검 대폭 강화 (Decade-old rules that never knew AI; vulnerability checks beefed up after breaches)](https://www.mt.co.kr/finance/2026/10/07/2026100616561411974); [Newspim](https://www.newspim.com/news/view/20261007000920)

### Inferences
- The pattern (ID enumeration against simplified-auth portals, low-rate requests, IP rotation) is classic broken-object-level-authorisation plus rate-limit evasion; an agentic scanner makes it cheap to repeat across many firms in days, which is consistent with the 28 Sept-4 Oct clustering.
- The absence of any CVE supports the independent-analyst view that the campaign exploited configuration and design weaknesses rather than novel software flaws.

### Gaps
- Shinhan has not publicly explained how the phone/identity-verification step was defeated.
- No technical breakdown found for KB, Hana, Busan, Yegaram, Welcome or Hyundai Capital beyond the system name.
- Whether any credentials (vs identifiers) were reused from prior leaks (true credential stuffing) is unconfirmed.

## What did Korean authorities say and do in the first week?

### Takeaway
Within ten days regulators moved from on-site inspection (30 Sept) to two emergency sector-wide meetings (2 and 4 Oct), mandatory self-checks with 6 and 8 Oct deadlines, distribution of 19 then 28 attack IPs to ~500 firms, a formal FSS examination of Shinhan running to 20 Oct, a 28-officer police investigation (6 Oct), presidential orders at Cabinet, and announced rule changes (shorter/wider vulnerability assessments, enforcement fines, CISO tenure, faster incident reporting), while keeping the network-separation easing policy. NIS and Bank of Korea roles in this specific incident were not found.

## Has anyone disputed the single-actor claim or the AI framing, and how much did AI tooling matter?

### Takeaway
No one has produced counter-evidence to CrowdStrike, but Korean police, the FSI and most independent analysts hold the line that AI's role is unproven in some breaches and that the decisive failures were ordinary (unassessed internet-facing portals with weak authentication); the ARTEX developer denies involvement, a man contacted via details in the report denied knowledge, and the viral "one person hacked nine banks with Claude Code" framing overstates both the count and Claude's role.

### Inferences
- The two camps are not actually in conflict: CrowdStrike's "single actor" is about who ran the campaign; Korean skeptics' point is about what let it succeed. Both can be true.
- The strongest objective evidence of AI involvement is CrowdStrike's exposed session data plus the FSI's ARTEX traces on Shinhan logs; the weakest link is tying the résumé/Telegram identity to the operator.

### Gaps
- No peer security vendor (Mandiant, Unit 42, Kaspersky, Korean firms other than AhnLab/FSI) has published an independent assessment confirming or disputing CrowdStrike.
- No formal fact-check of the viral social-media thread was found; its exact text and origin could not be identified.

## How does this compare with earlier AI-assisted intrusion reports such as Anthropic's 2025 GTG-1002 disclosure?

### Takeaway
GTG-1002 (Nov 2025) was a Chinese state-sponsored campaign in which a jailbroken Claude executed 80-90% of the operation across ~30 targets; the Korean case is a likely lone, financially motivated operator using a free open-source agent on cheap Chinese models, with Claude Code as a helper, hitting fewer organisations but exposing far more individuals via mundane weaknesses. The common thread analysts draw is that agentic tooling collapses the skill and staffing needed, not that the attacks became more technically sophisticated.

### Cited Findings
- GTG-1002: Anthropic attributed the Sept 2025 campaign to a Chinese state-sponsored group, which tricked Claude into believing it was a cybersecurity firm doing defensive testing; Claude executed 80-90% of the operation independently against about 30 organisations — [Paul Weiss client memo, "Anthropic Disrupts First Documented Case of Large-Scale AI-Orchestrated Cyberattack"](https://www.paulweiss.com/insights/client-memos/anthropic-disrupts-first-documented-case-of-large-scale-ai-orchestrated-cyberattack); [The Register, "Chinese spies used Claude to break into critical orgs" (13 Nov 2025)](https://www.theregister.com/2025/11/13/chinese_spies_claude_attacks/)
- Earlier precedents: Anthropic's Aug 2025 disruption of AI-powered theft/extortion across critical sectors — [The Hacker News, Aug 2025](https://thehackernews.com/2025/08/anthropic-disrupts-ai-powered.html); Sept 2026 report of Claude used to automate exploitation and data theft across multiple victims — [The Hacker News, Sept 2026](https://thehackernews.com/2026/09/claude-used-to-automate-exploitation.html)
- Korean case actor: likely a financially motivated individual, moderate confidence, not a named group — [TimesLIVE](https://www.timeslive.co.za/news/sci-tech/2026-10-08-crowdstrike-says-china-based-suspect-used-ai-tools-in-south-korean-bank-hacks/)
- Korean case AI role: a third-party agent (ARTEX) on DeepSeek did scanning/exploitation; Claude Code was used for planning, command generation and monetisation research — [The Hacker News](https://thehackernews.com/2026/10/artex-ai-pentesting-tool-used-in-data.html); [Infosecurity Magazine](https://www.infosecurity-magazine.com/news/chinese-hacker-ai-korean-banks/)
- Korean case scale: seven firms breached, ~68,000 people, via "mundane" initial access on internet-facing tools with weak authentication — [Korea Herald](https://www.koreaherald.com/article/10894542); [Security Point Break](https://securitypointbreak.com/2026/10/07/beyond-shinhan-south-koreas-bank-hacks-hit-66000-with-an-ai-clue/)
- Analysts see the free, open-source nature of ARTEX as the larger worry, and note small teams of low-resource but AI-savvy hackers could repeat the feat — [Startup Fortune, "AI hacking tool traced in South Korean bank breaches as CrowdStrike flags wider trend"](https://startupfortune.com/ai-hacking-tool-traced-in-south-korean-bank-breaches-as-crowdstrike-flags-wider-trend/); [The Decoder](https://the-decoder.com/ai-powered-hacking-tools-enabled-a-likely-single-attacker-to-breach-multiple-south-korean-banks/)
- Korean officials and press describe this as the first intrusion into a financial system using AI (a Korean "first", not a global one) — [Technology.org](https://www.technology.org/2026/10/06/south-korea-bank-hacks-ai-tools-lee-jae-myung/)
- An FSI official's "did not act independently" caveat contrasts with Anthropic's 80-90% autonomy figure — [American Banker](https://www.americanbanker.com/news/ai-linked-hacks-hit-korean-banks-through-loan-agent-sites); [Paul Weiss](https://www.paulweiss.com/insights/client-memos/anthropic-disrupts-first-documented-case-of-large-scale-ai-orchestrated-cyberattack)

### Inferences
- Method shift: GTG-1002 depended on jailbreaking a frontier closed model; the Korean operator avoided that problem by running an open-source agent on open-weight/Chinese models bought through a reseller, using Claude only for tasks that do not trip safety filters (research, résumé, planning). That is a harder problem for provider-side safeguards.
- Scale shift: fewer organisations but an order of magnitude more individuals exposed, because the targets were customer-data lookup portals rather than espionage targets.

### Gaps
- No analyst piece found that does a side-by-side of the two cases with technical depth; the comparison above is assembled from separate sources.
- Anthropic has not commented on whether the Claude Code sessions violated its usage policy or whether accounts were terminated.
